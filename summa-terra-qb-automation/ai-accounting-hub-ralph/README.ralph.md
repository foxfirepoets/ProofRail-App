## What ralph will build

The AI operating layer for legacy accounting systems: a canonical Postgres system-of-record fronting QuickBooks Enterprise Desktop (Rightworks) via an async QBWC adapter, with a Temporal human-approval commit boundary and a SwarmSync proof spine (InvoiceProof / AuditProof / VerifyAPI) as hard gates — delivered as a wedge-first 90-day MVP.

Chunks (8 total):
- CHUNK_1_INFRA: Stand up the canonical Postgres system-of-record with the initial multi-entity schema.
- CHUNK_2_TRANSPORT: Build the async QBWC SOAP endpoint and qbXML codec that reads one company file into the canonical store.
- CHUNK_3_CANONICAL: Expose unified cross-company search and a read API over the canonical store.
- CHUNK_4_AUDIT: Implement the AIVS hash-chain audit layer (AuditProof / Gate 2) as a hard pre-write gate.
- CHUNK_5_WORKFLOW: Wire the NATS event bus and Temporal commit-boundary with human approval gates.
- CHUNK_6_VERIFY: Add the VerifyAPI pre-execution gate (Gate 3) and gated qbXML write-back with optimistic locking.
- CHUNK_7_PAYMENTS: Implement the InvoiceProof AP money-movement gate (Gate 1) and bank-change/ATEP gate (Gate 4) with OCR intake.
- CHUNK_8_SCALE: Scale read sync to all 10 company files and prove the adapter seam with a QBO stub.

## Prerequisites

- Python 3.11
- FastAPI / FastMCP (+ Spyne/zeep for the QBWC SOAP endpoint)
- PostgreSQL (pgcrypto, pg_trgm)
- SQLAlchemy + Alembic
- NATS / JetStream
- Temporal (Python SDK)
- invoice2data (OCR/AP extraction)
- cryptography / PyNaCl (Ed25519)
- Docker + docker-compose
- Owner-operated SwarmSync (proof layer — in-process @swarmsync/proof-core or hosted REST with self-issued sa_* key)

## Setup Before First Run

1. Install dependencies: `pip install -r requirements.txt`
2. Copy environment file: `cp .env.example .env`
3. Fill in all required variables in `.env` (see AGENTS.md for the list)
4. Verify infra is running: `docker-compose up -d` then `pg_isready -h localhost`
5. Run migrations: `alembic upgrade head`

5. Restart the loop.

## Warnings from Spec Parsing

- Polyglot boundary: the build is Python 3.11, but the recommended in-process proof binding (`@swarmsync/proof-core`) is TypeScript. ralph should either (a) call the owner-hosted SwarmSync REST API with a self-issued `sa_*` key (pure-Python path, default in AGENTS.md), or (b) run a small Node sidecar exposing `runProofProduct`. Confirm the preferred mode before CHUNK_4.
- Two environment spikes precede the write path and are NOT code tasks: measure QBWC poll cadence on Rightworks, and obtain written Rightworks approval for a persistent poller. CHUNK_2 records the cadence metric; the approval ticket is operational.
- Spec was otherwise complete (tech stack, phases, risks, and out-of-scope all present).
